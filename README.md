# 米哈游国服活动日历

原神、崩坏：星穹铁道、绝区零国服的公开 ICS 订阅。仅收录游戏活动、卡池、更新维护、前瞻；不收社区杂项和爆料。默认提供开始/截止节点版，另有时间轴版。

## 数据与准确性

### 官方 B站前瞻补源

`sources/bilibili.json` 固定原神、星铁、绝区零国服官方 UID，仅采集前瞻预告；不把上传、回放、抽奖或版本上线时间当开播时间。与已收前瞻同一开播时刻的记录作为补充出处，不生成第二个 UID；新增独立候选先复核。匿名公开接口可能返回412/限流，遇验证立即停止；状态和自动 Issue 如实列出补源不可用，官网主源仍独立正常更新，不承诺 B站每轮都能抓到。

### 本机模型候选审核

使用硅基流动国内入口 `https://api.siliconflow.cn/v1`，固定模型 `Qwen/Qwen3.8-27B`。程序运行时只读外置密钥文件，不创建密钥副本、不打印凭据、不上传 GitHub。可通过 `SILICONFLOW_KEY_FILE` 指定私密路径；本机默认路径为 `E:/opencode归档/私密配置/siliconflow.key`。

`node scripts/review.mjs --live` 拉取公开待复核列表，再从官网/B站读当前原文和图片，输出到忽略提交的 `local-private/model-review.json`。原文引句、日期合法性、既有日程重复/冲突都会检查。图片会下载到内存并计算内容hash，使用base64发送给模型；没有把私密文件或整座工作区发送给服务。模型调用只发送公开官方资料，会产生服务费用。

**模型结果仅为候选，不直接发布，也不会自动改动已确认日程。** 图片识别、跨帖日期、版本边界、信息缺失仍留待复核。正文或图片超出预算则标证据不完整。每轮最多6篇、每篇3图、输出2400 token；输入与图片内容未变时跳过模型调用。候选缓存本机私有，不公开模型生成的未经确认日期。

Windows可运行 `scripts/install-review-task.ps1` 注册 `HoYoCN-LocalCandidateReview`，约每六小时执行 `scripts/review-local.ps1`。只在本机登录且可联网时工作，休眠关机期间不工作；恢复后由任务计划程序补执行。GitHub Actions继续承担官网采集、ICS生成与发布，不保存模型密钥。最终候选批准仍需维护会话；本机定时审核不等于自动发布或云端无人值守模型审核。

- 只从公开国服官方公告采集，所有事件附原文出处，时间为 UTC+8，ICS 使用 UTC 输出。
- **国服官网为主源**，正常更新不会请求米游社。只有官网请求失败才尝试米游社白名单官方账号；验证码或两源故障时保留既有日程，不要求登录或绕过验证。
- 绝区零优先走已验证的 `act-api-takumi-static.mihoyo.com` 官网内容服务，再试同服务 `api-takumi-static.mihoyo.com`；两者均不可用才退回米游社。来源状态保留实际服务入口，避免本机连通被误当成云端已通过。
- 来源适配器、官方身份筛选和每次采集状态可在仓库检查。
- 仅确定时间自动入日历。汇总、多阶段、图片日程进入待审核队列；明确维护开始和官方预计时长可生成标注“预计”的结束节点。
- “版本更新后”不擅自转成固定时刻，可以只发布确定的截止节点。
- 不靠固定六周周期预测新版本、卡池或前瞻，不发布未官宣日程。
- 来源失败或未再列出某条公告不会删除旧事件。取消和修改需按官方公告核对。
- 内容修改保留 UID 并增加 SEQUENCE；生成时间不会每天重置所有事件的修改时间。
- 节点版事件显示 15 分钟，仅为日历排版，不代表真实活动持续时间；未设置强制提醒。
- ICS 保留过去 120 天及未来一年内的已确认事件，仓库源数据保留历史。
- **谷歌外部订阅刷新由谷歌决定，无法保证即时更新或可靠临近截止提醒。** 发布频率不等于客户端刷新频率，ICS 的 VALARM 也不保证被谷歌采纳。

健康页的“采集成功”不等于覆盖全部活动；还需看待审核数量、更新时间和官方公告。纯图片中没有明确文字的时间不自动 OCR 猜测。

## 本地运行

Node.js 24 或更高，无第三方运行依赖，无需 `npm install`。

```sh
npm test
npm run update
npm run build
npm run check
```

`site/` 是生成后的部署目录。源码、状态、人工纠正记录在 Git 中；生成的 ICS 不直接提交，由 Actions 生成部署。

## 人工审核与纠正

查看 `data/review.json` 和仓库自动维护 Issue。核对国服官方原文后，在 `data/overrides.json` 添加事件：

```json
{
  "events": [
    {
      "id": "genshin:miyoushe:官方帖子ID:main",
      "game": "genshin",
      "category": "event",
      "title": "官方活动名称",
      "start": "2026-10-05T10:00:00+08:00",
      "end": "2026-10-20T03:59:00+08:00",
      "url": "https://www.miyoushe.com/ys/article/官方帖子ID",
      "notes": "经官方原文人工核对；此示例不能当真实活动。",
      "modified": "2026-10-03T01:00:00Z",
      "sequence": 0
    }
  ],
  "suppressPostIds": []
}
```

分类取 `event`、`banner`、`maintenance`、`livestream`。没有确定开始时间可用 `null`，前瞻须有开始时刻。同一帖子多个活动使用不同稳定后缀 ID。更新已发布事件保留 ID，增加 `sequence` 并更新 `modified`。官方宣布取消时将 `cancelled` 设为 `true`。不直接改自动采集事件，以免下次覆盖。

`suppressPostIds` 可填写完整事件 ID 或米游社帖子 ID，以隐藏误收录事件并标记审核处理。纯图片无法自动解析，需要人工录入；不能因为采集脚本成功就假报全部自动维护完成。

首次发布已人工核对当前复杂卡池及活动，确认依据见 `data/audit.json`。网页抽奖与社区活动不发布；星铁当前轮换挑战、限时时装优惠也作为游戏内限时信息收录。米游社备用采集仅主官方账号，暂不覆盖千星奇域独立官方账号。

`data/confirmations.json` 保存已人工确认的公告标题/正文 SHA256（键为 `游戏:来源:帖子ID`）。被确认的正文若变化，会重新进入未解决审核，不被已有人工覆盖静默掩盖。审核后重新记录 hash；同时核对跨帖子引用的日期来源。即使暂时没再扫到旧帖，也不据此认为旧日程被取消。

`data/aliases.json` 将官网和米游社同一公告关联到稳定的日历身份；`data/posts.json` 只保存标题、发布时间、原文链接与hash，不镜像全文。原有事件保留原ID/UID，不能因为来源切换改成第二条事件。不同期同名活动只在发布时间接近且唯一匹配时自动关联；异名、汇总、多卡池需人工核对关联。

官网默认读取综合栏目前100条（含置顶，不是严格按日期排序），具体覆盖以状态页为准，不承诺完整历史。历史候选只在核对实际截止或永久开放语义后标记处理，不仅凭发布日期认定活动已经结束。校验官网独立可用可用 `WEBSITE_ONLY=1` 运行 update，禁止备用调用。

## 自动运行与权限

- 每 6 小时的 UTC 第 23 分钟运行，并支持 Actions → 国服日历更新与发布 → Run workflow 手动运行。
- GitHub 调度可能延迟。公开仓库连续 60 天无活动时，定时工作流可能被禁用；正常数据提交形成活动，但不把此视为永久可用保证。
- 本项目只依赖仓库内的状态与 Issue 告警，**没有独立外部探针**；整个任务被停用时不能自行发送告警。维护者应关注最后成功更新时间与 Actions 通知。
- 只给构建任务内容写入和 Issue 写入权限，部署任务仅 Pages/OIDC 权限。不会执行来自 fork 的 PR 工作流。
- GitHub Pages 公开提供活动信息；不存游戏凭据、个人日历内容或 OAuth token。
- `scripts/github-*.mjs` 为维护者本机辅助工具，从系统 Git 凭据管理器使用授权；不会把授权写入项目或日志。工作流不运行本机辅助工具。

## 维护成本

程序可自动采集，但官方格式改动、图片公告和复杂时间语义仍需维护者审核。待审核和来源失败会集中在一个 Issue，避免重复建单。不能把这个项目当不需要任何维护的永久服务。

程序采用 MIT 许可；游戏名、图片及公告内容属于各自权利人。本项目非官方服务，只保留必要日程与原文链接，不镜像图片和整篇公告正文。
