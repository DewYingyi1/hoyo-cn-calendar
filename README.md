# 米哈游国服活动日历

原神、崩坏：星穹铁道、绝区零国服的公开 ICS 订阅。仅收录游戏活动、卡池、更新维护、前瞻；不收社区杂项和爆料。默认提供开始/截止节点版，另有时间轴版。

时间轴版在文件名增加 `-timeline`，例如 `genshin-timeline.ics`。「全部订阅」包含所有已接入游戏，链接为 `all.ics`，时间轴版为 `all-timeline.ics`；以后正式接入新游戏，继续使用同一链接。不要同时添加「全部订阅」与单款游戏订阅，否则相同游戏的日程会重复显示。

日程标题采用 `[游戏] 开启｜活动名` / `[游戏] 截止｜活动名`，把节点用途放在前面；说明使用中文日期，不显示原始ISO时间串。默认节点显示15分钟仅为排版占位，不是实际活动时长，也不代表设置了闹钟提醒。时间轴版有明确起止时展示实际区间；只有单个确定时刻时仍显示节点。

官网写明「2026/06/01 4.3版本更新后」等非精确时间时，网页与日程说明直接保留官方原文，不笼统显示成“未提供明确时间”。`startText` / `endText`保存经核对的原文；`start` / `end`只保存明确时刻，不能把“版本更新后”猜成预计维护结束或人为制造全天日程。仅缺少官方文字和明确时刻时才显示未提供明确时间。日历对外名称统一为「米哈游国服」，订阅链接与UID不变。

维护核对依据保存在 `data/*` 中。`notes` 保存证据与审核说明；人工记录另用 `displayNotes` 写面向阅读的简短语义（如限时奖励、购买提前关闭、分阶段开放）。网页与ICS只展示简短说明，不将公告编号、hash、身份迁移和核对过程塞入日历弹窗。`lib/calendar.mjs` 的展示修订号使已有订阅更新文案，UID和日期保持不变。

网页活动区按游戏收纳，手机和电脑均默认收起，不再提供“全部游戏”平铺筛选。游戏栏显示活动数量，点击“展开活动”才生成并显示该游戏的卡片；卡片先显示名称、分类及关键时间，点击“展开详情”查看完整起止、简短说明和官方原文。收起再展开会保留已打开的卡片状态，各游戏可独立展开。「全部订阅」链接不变。以后接入新游戏时，活动会按游戏键归入独立收纳栏；正式支持新游戏仍需配置来源、中文名称与订阅生成，不能仅凭网页分组视为已接入。

电脑端谷歌日历：其他日历 → ＋ → 通过网址添加 → 粘贴 HTTPS 链接。**不是下载后导入**，导入不会持续更新。朋友可直接使用同样的公开链接，不需要游戏登录或本仓库权限。

### Windows 电脑：WinCal / WinminiCal

[WinCal](https://github.com/ha0719/WinCal) 适合通过 HTTPS ICS 链接订阅本项目，在任务栏弹出月历和近期日程；它不是常驻桌面挂件。项目列出的系统要求为 Windows 10 1903+ 或 Windows 11。支持多份 ICS、缓存、可设刷新间隔和手动刷新，不需要游戏账号，也不必先订阅到 Google 日历。

一、打开[发布下载页](https://github.com/ha0719/WinCal/releases/latest)，在「Assets」（下载文件）中选择 `WinCal.exe`，运行并打开设置。

二、数据源选「ICS 订阅链接」，粘贴本页 HTTPS 地址，点击「添加」后「保存」。选择所需单款游戏或「全部订阅」，不要重复添加。

三、刷新间隔可选30分钟或1小时。源码在读取日历数据时检查缓存，过期则尝试后台更新；面板刷新按钮可强制重新下载。并非程序关闭后仍定时更新的独立服务。后台下载完成后若显示未变，可重新打开面板或手动刷新；离线/失败可能显示旧缓存。

WinCal 按系统本地时区显示；在中国大陆使用时核对电脑时区为 UTC+8。本项目约每6小时采集发布一次，客户端更频繁刷新不会加快官网采集。

依据 **1.0 发布标签源码** 核对远程下载、设置入口、缓存与手动刷新逻辑，未在本机安装或进行二进制兼容性实测：[`IcsCalendarService.cs`](https://github.com/ha0719/WinCal/blob/1.0/Core/Services/IcsCalendarService.cs)、[`SettingsWindow.xaml`](https://github.com/ha0719/WinCal/blob/1.0/Views/SettingsWindow.xaml)、[`PopupWindow.xaml.cs`](https://github.com/ha0719/WinCal/blob/1.0/Views/PopupWindow.xaml.cs)。

### Rainlendar：区分 Lite 与 Pro

**Rainlendar Lite 免费版不能原生订阅并自动刷新网络 ICS 链接。** Lite 能读取/导入本地 ICS，但下载导入只保留文件内容，不会自动拉取原网址的新日程。需要直接用链接持续订阅，应使用 **Rainlendar Pro** 的网络日历功能；[官网](https://www.rainlendar.net/)将网络日历等第三方集成功能列为 Pro 功能。

Lite 加外部定时下载和本地文件重载属于额外配置，并非内置网络订阅。不能将“刷新本地文件”或“重新导入”描述成自动订阅网址；未配置下载时，点击刷新也不会取回本网站新内容。

## 数据与准确性

### 仅官网采集

只主动采集原神、星铁、绝区零的国服官网公告。已删除 B站补源代码、配置与测试，也不再请求米游社或在官网失败时退回米游社。`sources/games.json` 只保存官网内容服务与公告链接配置；官网失败保留已有事件，并如实报告失败。下一次更新会清理旧状态中的 `supplemental`，不再显示旧补源状态。

历史 `miyoushe` canonical ID/ICS UID 与已发布事件中的官方米游社原文链接保留，不因仅官网采集而改写、删除或重复发布。它们代表历史身份和出处，不代表仍在采集米游社。当前官网正文、图片及确认 hash 继续按官网来源独立核对；解析器保留历史论坛/Quill格式兼容，但没有主动论坛请求。

### 本机模型候选审核

使用硅基流动国内入口 `https://api.siliconflow.cn/v1`，固定模型 `Qwen/Qwen3.8-27B`。程序运行时只读外置密钥文件，不创建密钥副本、不打印凭据、不上传 GitHub。可通过 `SILICONFLOW_KEY_FILE` 指定私密路径；本机默认路径为 `E:/opencode归档/私密配置/siliconflow.key`。

`node scripts/review.mjs --live` 拉取公开待复核列表，再仅从官网读匹配的当前原文和官网公告引用的官方图片，输出到忽略提交的 `local-private/model-review.json`。未匹配到官网正文的历史候选保留，但不会请求历史出处。非 live 模式同样过滤本机旧缓存中的米游社/B站输入，只接受配置官网链接与原始 `website` 来源；canonical 身份可以继续是历史 `miyoushe`。原文引句、日期合法性、既有日程重复/冲突都会检查。图片会下载到内存并计算内容hash，使用base64发送给模型；没有把私密文件或整座工作区发送给服务。模型调用只发送公开官网资料，会产生服务费用。

**模型结果仅为候选，不直接发布，也不会自动改动已确认日程。** 图片识别、跨帖日期、版本边界、信息缺失仍留待复核。正文或图片超出预算则标证据不完整。每轮最多6篇、每篇3图、输出2400 token；输入与图片内容未变时跳过模型调用。候选缓存本机私有，不公开模型生成的未经确认日期。

Windows可运行 `scripts/install-review-task.ps1` 注册 `HoYoCN-LocalCandidateReview`，约每六小时执行 `scripts/review-local.ps1`。只在本机登录且可联网时工作，休眠关机期间不工作；恢复后由任务计划程序补执行。GitHub Actions继续承担官网采集、ICS生成与发布，不保存模型密钥。最终候选批准仍需维护会话；本机定时审核不等于自动发布或云端无人值守模型审核。

- 只从公开国服官网公告采集，所有事件附原文出处（历史官方出处保留），时间为 UTC+8，ICS 使用 UTC 输出。
- **国服官网是唯一主动采集来源**，无米游社回退、无 B站补源；官网失败保留既有日程，不要求登录或绕过验证。
- 绝区零优先走已验证的 `act-api-takumi-static.mihoyo.com` 官网内容服务，再试同服务 `api-takumi-static.mihoyo.com`；两者均不可用则报告官网失败，保留旧事件。这是同一官网服务的备用入口，不是跨来源回退。来源状态保留实际服务入口，避免本机连通被误当成云端已通过。
- 来源适配器、官方身份筛选和每次采集状态可在仓库检查。
- 仅确定时间自动入日历。汇总、多阶段、图片日程进入待审核队列；明确维护开始和官方预计时长可生成标注“预计”的结束节点。
- “版本更新后”不擅自转成固定时刻，可以只发布确定的截止节点。
- 不靠固定六周周期预测新版本、卡池或前瞻，不发布未官宣日程。
- 来源失败或未再列出某条公告不会删除旧事件。取消和修改需按官方公告核对。
- 同一事件、同一节点的内容修改保留 UID 并增加 SEQUENCE；生成时间不会每天重置所有事件的修改时间。时间轴由单节点补成完整区间、拆分或移除已发布节点属于身份迁移，当前尚无自动退役节点账本，须单独核对，不能直接删除原记录当作取消。
- 节点版事件显示 15 分钟，仅为日历排版，不代表真实活动持续时间；未设置强制提醒。
- ICS 保留过去 120 天及未来一年内的已确认事件，仓库源数据保留历史。
- **谷歌外部订阅刷新由谷歌决定，无法保证即时更新或可靠临近截止提醒。** 发布频率不等于客户端刷新频率，ICS 的 VALARM 也不保证被谷歌采纳。

健康页的“采集成功”不等于覆盖全部活动；还需看待审核数量、更新时间和官方公告。纯图片中没有明确文字的时间不自动 OCR 猜测。

发布入口拒绝不存在的日期、无开播时刻的前瞻及非官方公告网址；下午/晚上时刻按明确语义换算，含糊表达和非北京时间送人工审核。取消/延期、同时间段的多个子活动、未写完整时刻的阶段、图片活动也进入审核；维护已解析不代表同篇更新说明的其他活动已审核。未解决审核不会仅因发现超过100天而清除。

## 本地运行

Node.js 24 或更高，无第三方运行依赖，无需 `npm install`。

```sh
npm test
npm run update
npm run build
npm run check
```

`site/` 是生成后的部署目录。源码、状态、人工纠正记录在 Git 中；生成的 ICS 不直接提交，由 Actions 生成部署。

## 人工审核与纠正

查看 `data/review.json` 和仓库自动维护 Issue。核对国服官网原文后，在 `data/overrides.json` 添加事件；新增公告使用官网身份与链接，已有事件继续沿用历史身份和出处。下面是新官网公告的格式示例，不是真实日程：

```json
{
  "events": [
    {
      "id": "genshin:website:官网公告ID:main",
      "game": "genshin",
      "category": "event",
      "title": "官方活动名称",
      "start": "2026-10-05T10:00:00+08:00",
      "end": "2026-10-20T03:59:00+08:00",
      "url": "https://ys.mihoyo.com/main/news/detail/官网公告ID",
      "notes": "经官方原文人工核对；此示例不能当真实活动。",
      "displayNotes": "简短说明活动或截止的含义，不写核对过程。",
      "modified": "2026-10-03T01:00:00Z",
      "sequence": 0
    }
  ],
  "replaceParentIds": [],
  "suppressPostIds": []
}
```

分类取 `event`、`banner`、`maintenance`、`livestream`。没有确定开始时间可用 `null`，前瞻须有开始时刻。同一帖子多个活动使用不同稳定后缀 ID。更新已发布事件保留 ID，增加 `sequence` 并更新 `modified`。官方宣布取消时将 `cancelled` 设为 `true`。不直接改自动采集事件，以免下次覆盖。

`suppressPostIds` 可填写完整事件 ID 或历史米游社帖子 ID，以隐藏误收录事件并标记审核处理。整篇父事件确需由子事件替换时，必须把父 ID 明确列入 `replaceParentIds`；仅仅新增 `父ID:子项` 不会再猜测父事件应被撤回。显式抑制、替换或 `cancelled:true` 会让已发布 UID 生成至少120天的取消墓碑；自然过期或源数据清理不会冒充取消。涉及拆分/节点变化须先核对原订阅身份。纯图片无法自动解析，需要人工录入；不能因为采集脚本成功就假报全部自动维护完成。

首次发布已人工核对当前复杂卡池及活动，确认依据见 `data/audit.json`。网页抽奖与社区活动不发布；星铁当前轮换挑战、限时时装优惠也作为游戏内限时信息收录。仅官网综合栏目范围内的公告参与新采集，不向米游社独立账号或 B站扩展补源。

`data/confirmations.json` 保存已人工确认的公告标题/正文 SHA256（键为 `游戏:来源:帖子ID`）。被确认的正文若变化，会重新进入未解决审核，不被已有人工覆盖静默掩盖。审核后重新记录 hash；同时核对跨帖子引用的日期来源。即使暂时没再扫到旧帖，也不据此认为旧日程被取消。

`data/aliases.json` 将官网公告和已有历史米游社记录关联到稳定的日历身份；不会为此请求米游社。`data/posts.json` 保存标题、发布时间、原文链接、正文hash、图片URL列表hash与确认基线，不镜像全文。标记为图片证据公告后，每轮会在官方域名、格式、单图16MiB、单篇32图、全轮64MiB与并发限制内核对原始字节；图片URL变化或同URL换字节都会持续送审。首次观察不会自动成为确认基线；人工确认当前正文后，须显式运行 `npm run approve-image -- <游戏:website:公告ID>`，并且当前正文digest、图片列表与完整观察字节全部一致才会绑定基线。未确认的跨源同名公告也不会写入alias或迁移旧事件。原有事件保留原ID/UID及历史官方出处，不能因为来源切换改成第二条事件；当前官网证据单独保存在官网来源的记录中。不同期同名活动只在发布时间接近且唯一匹配时形成身份候选；正式关联仍须当前来源人工确认。异名、汇总、多卡池需人工核对关联。

官网默认读取综合栏目前100条（含置顶，不是严格按日期排序），具体覆盖以状态页为准，不承诺完整历史。历史候选只在核对实际截止或永久开放语义后标记处理，不仅凭发布日期认定活动已经结束。所有更新默认且始终仅官网，不需要 `WEBSITE_ONLY` 环境开关。离线 `npm test` 覆盖官网失败无跨来源回退、历史ID/出处保留及模型输入来源过滤。

## 自动运行与权限

- 每 6 小时的 UTC 第 23 分钟运行，并支持 Actions → 国服日历更新与发布 → Run workflow 手动运行。
- GitHub 调度可能延迟。公开仓库连续 60 天无活动时，定时工作流可能被禁用；正常数据提交形成活动，但不把此视为永久可用保证。
- 本项目只依赖仓库内的状态与 Issue 告警，**没有独立外部探针**；整个任务被停用时不能自行发送告警。维护者应关注最后成功更新时间与 Actions 通知。
- 只给构建任务内容写入和 Issue 写入权限，部署任务仅 Pages/OIDC 权限。不会执行来自 fork 的 PR 工作流。
- GitHub Pages 公开提供活动信息；不存游戏凭据、个人日历内容或 OAuth token。
- `scripts/github-*.mjs` 为维护者本机辅助工具，从系统 Git 凭据管理器使用授权；不会把授权写入项目或日志。工作流不运行本机辅助工具。

## 维护成本

程序可自动采集，但官方格式改动、图片公告和复杂时间语义仍需维护者审核。待审核和来源失败会集中在一个 Issue，避免重复建单。不能把这个项目当不需要任何维护的永久服务。

程序采用 MIT 许可；游戏名、图片及公告内容属于各自权利人。本项目非官方服务，只保留必要日程与原文链接，不镜像图片和整篇公告正文。
